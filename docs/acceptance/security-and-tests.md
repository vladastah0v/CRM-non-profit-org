## Автотесты

`docker compose exec web pytest --cov` — 612 тестов, покрытие кода 92 %.

Что проверяют кроме отдельных функций:

- **Приёмочные сценарии 9.2** — `apps/core/tests/test_acceptance_92.py` и тесты, указанные
  в протоколе (docs/acceptance/protocol.md): у каждого из 13 сценариев есть автоматическая проверка.
- **Матрица прав 2.2** — `apps/core/tests/test_access_matrix.py`: каждый адрес приложения
  против каждой роли — разрешён или запрещён (403/404) по матрице. Объекты принадлежат
  «чужому» куратору: второй куратор не открывает их ни по прямой ссылке, ни через действия.
  Новый адрес без строки в таблице прав тест не пропустит.
- **Обезличивание и права субъекта** — `apps/consents/tests/`: после обезличивания ФИО,
  контакты и тексты стёрты и в таблицах истории, отчёты дают те же цифры.

## OWASP ZAP

`sh scripts/security/zap.sh` — пассивное (базовое) сканирование всех страниц под сессией
администратора: паук обходит приложение и админ-панель, ZAP проверяет ответы.
Результат: **0 нарушений (FAIL), 54 правила пройдены, 13 предупреждений.** Полный отчёт — `tmp/zap-report.html`.

Активные атаки (`zap-full-scan`) на компьютере разработчика не запускались — они меняют данные.
Их проводят на тестовом сервере по согласованию с фондом (см. «Что остаётся» ниже).

| Предупреждение | Где | Оценка |
|---|---|---|
| CSP: `unsafe-inline`, `unsafe-eval` (Medium) | Только админ-панель | Админ-панель Unfold без них не работает. Основное приложение — строгая CSP `script-src 'self'`. Админ-панель доступна только администраторам с 2FA по нестандартному адресу `DJANGO_ADMIN_URL`. **Принятый риск** |
| CSP и Permissions-Policy не заданы (Medium, Low) | `/accounts/logout/`, `/admin/logout/` | Особенность стенда: выход на нём закрыт ответом 403 без заголовков, чтобы паук не завершил сессию. На сервере эти адреса отдаёт приложение с полным набором заголовков. **Не дефект** |
| X-Content-Type-Options (Low) | Статика `/static/` | На стенде — Nginx разработки. В рабочей конфигурации (`docker/nginx/prod.conf.template`) для статики выставлен `nosniff`. **Не дефект** |
| Private IP Disclosure (Low) | Журнал аудита в админ-панели | Это IP-адреса входов — их журнал хранит по требованию НФТ-ИБ-07; виден только администратору. **Так задумано** |
| Cross-Origin-Embedder/Resource-Policy (Low) | Страницы приложения | Нужны для изоляции между сайтами (SharedArrayBuffer и т. п.), Система этим не пользуется; встраивание запрещено `frame-ancestors 'none'`. **Не применимо** |
| Dangerous JS Functions (Low) | Библиотека htmx | `eval` внутри htmx для атрибутов `hx-on`; Система их не использует, а CSP без `unsafe-eval` его блокирует. **Не дефект** |
| User Controllable HTML Attribute (Info) | Фильтры списков | Значения фильтров возвращаются в форму; Django экранирует их при выводе. **Не дефект** |
| Storable and Cacheable Content (Info) | Главная, задачи, отчёты | В первом прогоне страницы за входом отдавались без запрета кэширования. **Исправлено** (замечание № 1 ниже); в повторном прогоне ZAP отмечает их как Non-Storable |
| Suspicious Comments, Modern Web Application, Non-Storable Content, Authentication Request, Session Management (Info) | Разное | Информационные: ZAP отмечает форму входа, cookie сессии, комментарии в библиотеках JS админ-панели Django. **Не дефект** |

## Резервное копирование и восстановление

`sh scripts/backup/restore-test.sh` — изолированный проект Docker Compose, S3Mock вместо
хранилища в РФ, те же образ, скрипты и шифрование копий (libsodium), что на сервере.
Копию делает отдельный контейнер `backup`, как на сервере: подключается к базе по сети,
том данных — только для чтения.

1. База-источник: 1 000 000 строк, полная копия WAL-G.
2. После копии записано ещё 1 000 строк — они должны вернуться из архива WAL.
3. Источник остановлен; копия развёрнута в пустой том «нового сервера», PostgreSQL проиграл WAL.

Результат: **1 001 000 строк, контрольная сумма совпала, включая записи после копии.
Восстановление — 13 с** (требование сценария 9.2 № 12 — не более 4 часов на чистом сервере).

Время растёт с объёмом базы и архива WAL. Полную проверку на чистом сервере по
docs/deploy.md с замером времени проводят при приёмке (протокол, сценарий 12).

## Роль приложения в PostgreSQL

Проверено на чистой базе, созданной серверным скриптом `docker/postgres/init/10-app-role.sh`:
миграции — от роли-владельца `crm`, затем приложение от роли `crm_app` наполнило базу
(`manage.py prepare_e2e`: сотрудники, карточки, согласия, 11 записей журнала аудита).

| Действие от `crm_app` | Результат |
|---|---|
| Чтение и изменение рабочих таблиц | Разрешено |
| `UPDATE`, `DELETE`, `TRUNCATE` журнала аудита | Отказ: permission denied |
| Отключить триггеры журнала аудита | Отказ: must be owner |
| `DROP`, `ALTER`, `TRUNCATE` рабочей таблицы | Отказ |
| Создать новую таблицу | Отказ: permission denied for schema public |

Значит, даже при взломе приложения журнал аудита нельзя подчистить через его подключение к базе.

5. **Оценка специалиста по защите информации** — уровень защищённости ИСПДн и перечень мер
   (НФТ-ПД-07, docs/security.md).

| № | Замечание | Уровень | Решение |
|---|---|---|---|
