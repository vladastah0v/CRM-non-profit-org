# Telegram-бот для волонтёров

Раздел 7.2 ТЗ, ФТ-С-02, ФТ-У-01. Через бота волонтёр видит свои смены и визиты,
записывается на открытые смены, подтверждает участие («Приду» / «Не смогу») и после
смены отмечает явку и часы. Часы сразу попадают в карточку волонтёра.

## Как устроено

```
 Волонтёр ──Telegram──> бот (сервис bot, aiogram 3, long polling)
                          │  только HTTP: http://web:8000/api/v1/bot/ + сервисный токен
                          ▼
                        Django ──> PostgreSQL
                          ▲
 Celery Beat ──> Celery ──┴──> Telegram Bot API: напоминания за 24 и 2 часа, после смены — «отметьте участие»
```

- Бот — отдельный процесс без доступа к базе. Он сидит в отдельной сети Docker (`bot`):
  видит только `web`, но не `db` и `redis`. Переменные окружения у него свои, без ключей
  шифрования и пароля базы.
- Бот ходит в CRM с **сервисным токеном** с правом `bot`. В базе хранится только SHA-256
  токена; отзыв — «Перевести в архив» в админ-панели («Сервисные токены»).
- Снаружи путь `/api/v1/bot/` закрыт в Nginx — API доступен только внутри Docker.
- Напоминания отправляет Celery напрямую через Telegram Bot API (тот же токен бота).
  Кнопки в напоминаниях обрабатывает процесс бота.
- Бот отвечает только в личных чатах: в группе сведения о визите увидели бы посторонние.

## Подключение

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`. Название —
   например «Волонтёры фонда …», имя — на `_bot`. BotFather пришлёт токен бота.
   Токен — секрет: кто его знает, может писать от имени бота.
2. Выпустите сервисный токен API для процесса бота:

   ```bash
   docker compose exec web python manage.py issue_service_token "Telegram-бот" --scope bot
   ```

   Токен показывается один раз — сразу перенесите его в `.env`.
3. Заполните `.env`:

   ```ini
   TELEGRAM_BOT_TOKEN=123456:ABC…        # от BotFather
   TELEGRAM_BOT_USERNAME=fond_volunteers_bot
   BOT_API_TOKEN=crm_…                   # из шага 2
   ```

4. Перезапустите Celery (он читает `TELEGRAM_BOT_TOKEN`) и запустите бота:

   ```bash
   docker compose up -d celery beat web
   docker compose --profile bot up -d bot
   docker compose logs -f bot          # «Start polling» — бот работает
   ```

   На сервере — с файлами `-f docker-compose.yml -f docker-compose.prod.yml`.

Если `TELEGRAM_BOT_TOKEN` пуст, CRM работает как раньше, просто без сообщений в Telegram.

## Привязка волонтёра

1. Координатор открывает карточку волонтёра → блок «Telegram-бот» → «Выдать код».
   Код вида `ABCD-EFGH` показывается один раз и действует 72 часа. В базе хранится
   только его HMAC.
2. Координатор передаёт код волонтёру лично или по телефону.
3. Волонтёр открывает бота, нажимает «Старт» и отправляет код. Telegram ID сохраняется в
   карточке, код стирается.

Если волонтёр сменил телефон — выдать новый код («Код для нового телефона»): новый
Telegram заменит старый. «Отвязать» в карточке или команда `/unlink` в боте выключают
доступ. Выбывший волонтёр и карточка в архиве доступа к боту не имеют.

Подбор кода затруднён: восемь знаков из 31 символа (≈ 2⁴⁰ вариантов), не больше
10 попыток в час с одного Telegram.

## Что видит волонтёр

| Меню / команда | Что делает |
|---|---|
| «Мои смены», `/shifts` | Ближайшие смены и визиты; кнопки «Приду», «Не смогу», «Подробнее» |
| «Записаться на смену», `/signup` | Открытые смены на 30 дней вперёд: запись открыта, есть места, все требуемые навыки есть у волонтёра, район его или не указан |
| `/help` | Подсказка |
| `/unlink` | Отвязать Telegram |

- **Напоминания:** за сутки — с вопросом «Вы придёте?» и кнопками, за 2 часа — ещё раз.
  Если назначили меньше чем за сутки, сообщение о назначении заменяет первое напоминание.
- **После смены:** «Был(а), N ч» (N — длительность смены), «Другое число часов»,
  «Не смог(ла) прийти». Отметить можно в течение двух суток. Отметку координатора
  волонтёр изменить не может.
- **Визит к подопечному:** в сообщениях — только время. Имя подопечного, адрес, телефон
  и комментарий к заданию — по кнопке «Подробнее о визите», пока визит не прошёл
  (+2 часа) и пока случай «в работе». Каждый показ пишется в журнал аудита.
- **Отказ** («Не смогу») — уведомление в CRM тому, кто создал смену или визит
  (если он не координатор — всем координаторам).

## Внутренний API

`Authorization: Bearer <BOT_API_TOKEN>`, `X-Telegram-User-Id: <id>`. Документация
OpenAPI — `/api/v1/docs/` (только сотрудникам).

| Метод и путь | Что делает |
|---|---|
| `POST link/` `{"code"}` | Привязать Telegram по коду |
| `POST unlink/` | Отвязать |
| `GET me/` | Имя, статус, часы |
| `GET assignments/` | Мои предстоящие назначения и те, где нужна отметка явки |
| `GET assignments/<id>/` | Подробности; для визита — данные подопечного, если разрешено |
| `POST assignments/<id>/confirm/`, `…/decline/` | «Приду» / «Не смогу» |
| `POST assignments/<id>/attendance/` `{"attended", "hours"?}` | Явка и часы |
| `GET shifts/` | Открытые смены для записи |
| `POST shifts/<id>/signup/` | Записаться |

Ответ 403 с `"code": "not_linked"` — Telegram не привязан; 400 с `detail` — правило не
выполнено (текст показывается волонтёру как есть).

## Пилот на 5–10 волонтёрах (результат этапа 7)

1. Подключить бота на тестовом сервере (раздел «Подключение»), заполнить справочник
   «Типы смен».
2. Выбрать 5–10 активных волонтёров с Telegram, выдать им коды привязки.
3. Создать 2–3 смены на ближайшую неделю: одну — с открытой записью, одну — с назначением
   координатором, одну — с требуемым навыком.
4. Проверить вместе с волонтёрами: запись через бота, напоминание за сутки и «Приду»,
   «Не смогу» (координатору приходит уведомление), отметку явки после смены, часы в
   карточке, визит к подопечному (данные видны до визита и скрываются после).
5. Собрать замечания по текстам и кнопкам; ошибки — в трекер с кодами требований.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Бот не отвечает | `docker compose logs bot`: задан ли `TELEGRAM_BOT_TOKEN`, есть ли «Start polling» |
| «Бот временно не работает» | Токен `BOT_API_TOKEN` отозван или неверен — выпустить новый |
| «Сервис временно недоступен» | Запущен ли `web`; бот обращается к `http://web:8000` |
| Нет напоминаний | Запущены ли `celery` и `beat`, задан ли `TELEGRAM_BOT_TOKEN` в их окружении; привязан ли волонтёр |
