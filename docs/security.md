# Безопасность: что сделано и что остаётся

Раздел 5 ТЗ (152-ФЗ, НФТ-ИБ). Уровень защищённости ИСПДн и итоговый перечень мер
подтверждает специалист по защите информации (НФТ-ПД-07).

## Сделано в ядре (этап 3)

| Требование | Как реализовано |
|---|---|
| НФТ-ИБ-02 2FA | Пароль → TOTP. Устройство привязывается только с одноразовым кодом от администратора (72 ч). Секрет TOTP в БД зашифрован |
| НФТ-ИБ-03 пароль, блокировка | ≥ 12 символов, Argon2. 5 неудачных попыток пароля или кода → блокировка 15 мин. Одинаково для существующих и несуществующих логинов, включая время ответа |
| НФТ-ИБ-04 тайм-аут | Сессия 30 мин с продлением при активности; на ввод кода после пароля — 5 мин |
| НФТ-ИБ-05 шифрование | AES-256-GCM, ключи в переменных окружения, ротация (`rotate_encryption_keys`). Шифротекст привязан к модели и полю |
| НФТ-ИБ-07 аудит | Вход/выход, неудачи, блокировки, права, 2FA, пароли, скачивания. Только добавление: запрет в ORM и триггерами PostgreSQL, время ставит база. Без ФИО и значений полей |
| НФТ-ИБ-08 IDOR | Выборки только через `visible_to(user)`; ссылка на файл привязана к пользователю, права проверяются при каждом скачивании |
| НФТ-ИБ-11 файлы | Тип по содержимому, ≤ 20 МБ, шифрование, выдача только через приложение по ссылке на 5 мин |
| Сбор ошибок | Без локальных переменных, тела запроса, cookie и заголовков |

## Сделано в модуле «Волонтёры» (этап 4)

| Требование | Как реализовано |
|---|---|
| Матрица 2.2, НФТ-ИБ-08 | `Volunteer.objects.visible_to(user)`: координатор и администратор — всё; куратор — только набор «О» (поля вне набора не загружаются из базы), без архива; аналитик — ничего. Изменения — только «П»-роли, отказ до поиска записи |
| Приём анкет (п. 7.1) | HMAC-SHA256 от «время.тело», окно ±5 мин, повтор подписи отклоняется, 10 запросов/мин с IP (IP — как во всём проекте, подмена X-Forwarded-For не помогает), тело ≤ 64 КБ. Ответ не раскрывает, есть ли человек в базе |
| Файлы карточек | Координатор видит сканы согласий и фото волонтёров; куратор — нет. Фото показывается в карточке только для JPEG/PNG/WEBP, остальное — скачивание |
| ПДн в побочных данных | Текст поиска не сохраняется в фильтрах; уведомления без ФИО; журнал аудита — только id и названия полей |

## Сделано в модуле «Подопечные» (этап 5)

| Требование | Как реализовано |
|---|---|
| Матрица 2.2, п. 2.3 | Куратор видит только своих подопечных (ответственный или открыт доступ руководителем) — в списке, поиске, по ссылке, в файлах. Координатор — набор «О» (поля вне набора не загружаются). Аналитик — ничего. Назначает кураторов и открывает доступ только администратор, каждое изменение — `PERMISSION_CHANGE` в аудите |
| ФТ-П-03, НФТ-ИБ-05 | Здоровье, инвалидность, паспорт, СНИЛС — `EncryptedTextField`, в том числе в таблице истории; ротация ключей перешифровывает и историю. Сканы документов зашифрованы |
| НФТ-ИБ-07 | Каждое открытие защищённого блока — `VIEW_SENSITIVE`; страница не кэшируется |
| НФТ-ПД-03 | Здоровье и инвалидность не сохраняются без действующего согласия на особые категории |
| ФТ-Д-02, ФТ-Д-03 | Без согласия случай не берётся в работу и не редактируется в работе; отзыв переводит случай на паузу, администраторы получают уведомление об обезличивании |
| ФТ-П-06 | Предупреждение о дубле не раскрывает чужую карточку: только факт совпадения и куратор |

## Сделано в модулях «Заявки и помощь», «Взаимодействия» (этап 6)

| Требование | Как реализовано |
|---|---|
| Матрица 2.2 | Заявки и помощь: куратор — своих подопечных (и заявки, где он ответственный), координатор — только чтение, аналитик — нет доступа к записям (агрегаты — в отчётах этапа 8). Взаимодействия: куратор — свои подопечные, координатор — волонтёры, правит только автор |

## Сделано в модуле «Смены» и Telegram-боте (этап 7)

| Требование | Как реализовано |
|---|---|
| Матрица 2.2 | Смены и назначения: администратор и координатор — П, куратор — чтение (визиты — только к своим подопечным), аналитик — нет доступа к записям, волонтёр — только свои назначения через бота |
| п. 2.3, 7.2 | Волонтёр получает имя подопечного (без фамилии), адрес, телефон и комментарий к заданию — только по запросу, пока визит предстоит (+2 ч) и случай «в работе». Каждый показ — `VIEW_SENSITIVE` в аудите. В сообщениях Telegram данных подопечного нет. Закрытие, пауза (в т. ч. отзыв согласия) и архив случая снимают визиты |
| п. 7.2, 7.5 | Бот без доступа к базе, в отдельной сети Docker. Сервисный токен с правами (`scopes`), в базе — SHA-256, отзыв — архив. Путь `/api/v1/bot/` закрыт в Nginx снаружи. Сессия сотрудника к API бота не подходит |
| Привязка | Одноразовый код на 72 ч, в базе — HMAC; 10 попыток в час на Telegram ID; один Telegram — одна карточка. Выбывший волонтёр и архивная карточка теряют доступ |
| Журналы | Тексты сообщений и Telegram ID не пишутся в логи ни CRM, ни бота |

## Сделано на этапе 8: отчёты, выгрузки, импорт, обезличивание

| Требование | Как реализовано |
|---|---|
| ФТ-О-04, п. 7.3 | Выгрузка — той же выборкой, что экран (`visible_to` + фильтры), набор колонок по правам; координатору — только поля «О», в том числе по чужим подопечным у совмещённой роли «куратор + координатор». Защищённый блок и тексты заявок не выгружаются. Каждая выгрузка — `EXPORT` в аудите без текста поиска. Ответ `Cache-Control: no-store`. В XLSX текст никогда не становится формулой |
| Матрица 2.2, «Отчёты» | Аналитик видит только агрегаты (без ФИО), куратор — отчёт по своим подопечным, координатор — по волонтёрам |
| ФТ-А-04 | Обезличивание стирает ФИО (остаётся код), контакты, адрес, Telegram, представителей и связанных лиц, файлы, защищённый блок, тексты заявок, взаимодействий, задач и комментариев — и копии в таблицах истории. Факты помощи, часы, статусы остаются. Карточку нельзя вернуть из архива. Событие `ANONYMIZE` с основанием |
| ФТ-Д-03 | Отзыв последнего действующего согласия создаёт запрос на обезличивание со сроком 30 дней (ч. 5 ст. 21 152-ФЗ); в карточке — предупреждение, у администратора — список запросов. Снять запрос можно только с указанием основания — в аудит |
| ФТ-А-05 | Импорт — только администратор. Файл — до 5 МБ и 5000 строк, XLSX проверяется на размер после распаковки (zip-бомба), XML разбирается через defusedxml; хранится зашифрованным и удаляется после импорта. Каждая строка проходит те же правила, что ручной ввод |
| п. 7.1 | Обращения подопечных с сайта — та же подпись HMAC, защита от повторов и лимиты, что у анкет волонтёров; форма не спрашивает о здоровье и документах |
| п. 3.10, 9.1 | Глобальный поиск — через выборки списков с проверкой прав: чужой подопечный не находится |

HTTP внутри одного сервера (сеть Docker); если бот переедет на другой сервер — только через HTTPS.

## Принятые остаточные риски

- Ссылка на файл многоразовая в течение 5 минут (одноразовость — по решению фонда).
- Шифротекст поля не привязан к конкретной записи: перенос значения между записями
  одной таблицы требует прямого доступа на запись в БД.
- Записи журнала аудита старше года автоматически не удаляются (ТЗ: «не менее 1 года»).
  Срок хранения IP-адресов в журнале — решение фонда с юристом (этап 0).
- Неудачная попытка учитывается после проверки пароля: несколько параллельных запросов
  успевают пройти проверку блокировки. Окно ограничено лимитом Nginx (burst 10).
- Любой может заблокировать чужую учётную запись на 15 минут, вводя неверный пароль, —
  это свойство требования НФТ-ИБ-03.
- Команда `issue_2fa_code` печатает код подключения в консоль: не запускайте её в
  окружении, где вывод уходит в общий лог.
- Лимит приёма анкет (10 в минуту) действует на IP сервера сайта, то есть на все анкеты
  фонда вместе. Защита от ботов — капча на стороне сайта.
- Админ-панель (Unfold) работает с CSP `'unsafe-inline' 'unsafe-eval'` — без них она не
  открывается. Основное приложение — строгая CSP; админ-панель доступна только роли
  «Администратор» после 2FA, по адресу из `DJANGO_ADMIN_URL`.

## Правила для разработчиков

- **Не переименовывать модели и поля с `EncryptedTextField`** без миграции перешифровки:
  шифротекст привязан к имени модели и поля, после переименования он не расшифруется.
- Не ослаблять CSP (`docker/nginx/snippets/security-headers.conf`) без ревью.
